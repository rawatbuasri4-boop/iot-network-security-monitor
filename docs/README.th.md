# IoT Network Security Monitoring Simulator

โปรเจกต์จำลองสำหรับเรียนรู้ระบบตรวจจับความผิดปกติของเครือข่าย IoT โดยไม่ต้องต่อวงจรหรือมี Raspberry Pi จริง

## วิธีเปิดใช้งานบน Windows

ดับเบิลคลิก `OPEN_DASHBOARD.html` จาก File Explorer แล้วใช้ Dashboard ใน Chrome หรือ Edge ได้ทันที ไม่ต้องรัน Python หรือเปิด localhost

`start_simulator.bat` จะเปิด Dashboard แบบนี้ให้เช่นกัน

โหมดนี้สร้างข้อมูลจำลองและตรวจจับในเบราว์เซอร์ทั้งหมด บันทึกรายการอุปกรณ์ที่อนุมัติและข้อมูลล่าสุดใน localStorage ของเบราว์เซอร์ ไม่เขียนข้อมูลลง `simulator.db` หากเบราว์เซอร์ไม่อนุญาต localStorage ยังทดลองได้แต่ข้อมูลจะหายเมื่อปิดหน้าเว็บ

ปุ่ม Reset ล้างเฉพาะข้อมูลการจำลองของโหมดที่เปิดอยู่ Alert เก่ายังคงแสดงเป็นประวัติหลังอนุมัติอุปกรณ์แล้ว

## หน้าเว็บ IoT Watch แบบใหม่

- **ภาพรวมเครือข่าย**: ดูแผนผังอุปกรณ์ → เราเตอร์ → ปลายทาง กดที่อุปกรณ์เพื่อดูรายละเอียด
- **ถ้าเกิดเหตุการณ์นี้ล่ะ?**: กดเลือกการใช้งานปกติ อุปกรณ์ใหม่ กล้องติดต่อหลายพอร์ต หรือปลั๊กส่งข้อมูลรัว ๆ พร้อมอ่านคำอธิบายใต้ปุ่ม
- **สีของอุปกรณ์**: เขียว = อยู่ในเกณฑ์ปกติ, เหลือง = ยังไม่ได้อนุมัติ, แดง = พบพฤติกรรมเกินเกณฑ์
- **อุปกรณ์ของฉัน**: ตรวจสอบ IP และสถานะ กดอนุมัติเฉพาะอุปกรณ์ที่รู้จัก การอนุมัติไม่ปิดกฎตรวจจับความผิดปกติ
- **ประวัติแจ้งเตือน**: อ่านเหตุการณ์ย้อนหลัง ประวัติยังอยู่หลังอนุมัติหรือกลับมาใช้งานปกติ
- **กราฟจังหวะการส่งข้อมูล**: แสดงจำนวนข้อความต่อวินาทีโดยประมาณจากผลต่างจำนวน Packet ระหว่างการอัปเดต ไม่ใช่จำนวนผู้เข้าเว็บไซต์
- **พักการจำลอง / จำลองต่อ**: หยุดและเริ่มสร้างข้อมูลจำลองได้ เปิดรายละเอียดอุปกรณ์อ่านได้ระหว่างพัก
- **เริ่มใหม่**: มีหน้าต่างยืนยันก่อนล้างข้อมูลการทดลองของโหมดที่เปิดอยู่
- **ข้อมูลการสื่อสารแบบละเอียด**: พับไว้ในหน้าแรก เปิดดูและค้นหา IP, ชื่ออุปกรณ์, Protocol หรือ Port ได้
- **เข้าใจโปรเจกต์นี้**: มีภาพรวม 4 ขั้นตอน วิธีลองครั้งแรก และคำศัพท์ภาษาไทย

แผนผังเป็นภาพแนวคิดของเครือข่ายจำลอง ไม่ใช่แผนผังที่ค้นพบจากเครือข่ายจริง จำนวนที่ “ต้องตรวจสอบตอนนี้” แสดงสถานะปัจจุบัน แยกจากจำนวนแจ้งเตือนที่เก็บไว้เป็นประวัติ เมื่อกลับมาส่งข้อมูลปกติ ระบบอาจใช้เวลาสูงสุดประมาณ 20 วินาทีเพื่อให้ข้อมูลเดิมพ้นช่วงตรวจจับ อุปกรณ์ที่ยังไม่อนุมัติจะยังถูกแสดงให้ตรวจสอบต่อไป

### รันจาก VS Code

1. เปิดโฟลเดอร์โปรเจกต์นี้ใน VS Code
2. ไปที่เมนู `Terminal > New Terminal`
3. พิมพ์คำสั่งแล้วกด Enter:

   ```text
   .\start_simulator.bat
   ```

4. Dashboard แบบเปิดจากไฟล์จะเปิดในเบราว์เซอร์โดยอัตโนมัติ

### โหมด Python Server และ SQLite (ตัวเดิม)

สำหรับพัฒนาฝั่ง Backend ให้รัน:

```text
.\start_simulator.bat --server
```

หรือ `python iot_security_simulator.py --open-browser` เปิด Terminal ค้างไว้ระหว่างใช้งาน เมื่อเห็นข้อความ `IoT Security Simulator running at ...` เปิดที่:

   ```text
   http://127.0.0.1:8765
   ```

ถ้าเครื่องเชื่อมต่อ localhost ไม่ได้ ใช้ `OPEN_DASHBOARD.html` เพื่อทดลองฟังก์ชันทั้งหมดในเบราว์เซอร์ได้ โหมด Server ใช้ Python Standard Library โดยไม่ต้องติดตั้งไลบรารีเพิ่มเติม

ถ้าเครื่องขึ้น `No installed Python found!` เมื่อใช้ `py` ให้ใช้ `python iot_security_simulator.py --open-browser` แทน ตัวเปิดเวอร์ชันนี้จะลองใช้ `python` ก่อน แล้วค่อยใช้ `py -3` สำรอง ต้องใช้ Python 3.10 ขึ้นไป

## สิ่งที่ระบบจำลองได้

- Traffic ปกติจาก Thermostat, Camera และ Smart Plug
- อุปกรณ์ใหม่ที่ไม่อยู่ในรายการ
- การติดต่อหลาย Port ในเวลาสั้น ๆ
- Traffic พุ่งสูงผิดปกติ
- การเก็บ Events และ Alerts ลง SQLite ที่ไฟล์ `simulator.db`
- Web Dashboard สำหรับดู Devices, Events และ Security Alerts
- กดอนุมัติอุปกรณ์ใหม่จากหน้า Dashboard เพื่อเปลี่ยนเป็นอุปกรณ์ที่เชื่อถือได้

## ไฟล์สำคัญ

- `iot_security_simulator.py` — Backend, simulator, detection rules และ API
- `OPEN_DASHBOARD.html` — ดับเบิลคลิกเพื่อเปิดระบบแบบไม่ต้องใช้เซิร์ฟเวอร์
- `static/simulator.js` — ตัวสร้างข้อมูลและกฎตรวจจับสำหรับโหมดเบราว์เซอร์
- `static/index.html` — หน้า Dashboard
- `static/app.js` — การดึงข้อมูลและแสดงผล
- `static/styles.css` — รูปแบบหน้าเว็บ
- `simulator.db` — สร้างอัตโนมัติเมื่อเปิดระบบครั้งแรก

## ขอบเขตโปรเจกต์สำหรับรายงาน

สามารถอธิบายระบบเป็น 4 ชั้น:

1. Traffic Generation — สร้างข้อมูลจำลอง
2. Feature Extraction — ดึง IP, Protocol, Port และขนาด Packet
3. Detection Engine — ใช้กฎตรวจจับ Unknown Device, Port Scan Pattern และ Traffic Burst
4. Presentation & Storage — แสดงผลผ่าน Dashboard และบันทึกลง SQLite

## Workflow เมื่อพบอุปกรณ์ใหม่

1. ระบบเห็น IP/MAC ที่ไม่อยู่ในรายการ
2. Detection Engine สร้าง Alert
3. ผู้ดูแลตรวจสอบว่าเป็นอุปกรณ์ที่อนุญาตหรือไม่
4. ถ้าอนุญาต ให้กด `อนุมัติอุปกรณ์`
5. ระบบเปลี่ยนสถานะเป็น `Trusted` และไม่แจ้งเตือนซ้ำสำหรับอุปกรณ์นั้น

ข้อมูลในระบบนี้เป็นข้อมูลจำลองและควรใช้เพื่อทดสอบในเครื่องหรือเครือข่ายที่ได้รับอนุญาตเท่านั้น
